# Code of conduct

Participants in VetraDB issues, reviews and other project spaces must treat each other respectfully. Technical criticism and disagreement are welcome; harassment, threats, discriminatory conduct, doxxing, sexual harassment and disclosure of private information or credentials are prohibited.

## Reporting and enforcement

For abusive content, use GitHub's **Report content** action on the issue, pull request or comment. If reporting to repository administrators is offered, that reaches project maintainers; otherwise select GitHub Support. For sensitive concerns, or concerns about the sole maintainer, use [GitHub's abuse reporting contact form](https://support.github.com/contact/report-abuse). These routes are documented in [GitHub's reporting guide](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam); a report does not require a public issue or a published personal email address.

Include the relevant links, dates and minimal evidence. Do not disclose personal data or private conversations in a public thread. GitHub handles reports sent to its support channel under its own policies; the project does not promise access to those reports or a response SLA. Security vulnerabilities use [SECURITY.md](SECURITY.md), not conduct reports.

The initial project enforcer is [ulrichheringer](https://github.com/ulrichheringer), subject to the independent GitHub Support route above. Maintainers may request correction, remove content, restrict participation or revoke access in proportion to the conduct, taking reporter safety and conflicts of interest into account. Publish only a sanitized explanation when appropriate; never retaliate against good-faith reporters. Questions about a project enforcement decision may be raised through the same private reporting route.
