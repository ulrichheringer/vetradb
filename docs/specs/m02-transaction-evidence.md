# M02 transaction implementation and evidence

Implemented for [epic #3](https://github.com/ulrichheringer/vetradb/issues/3), TXN-001 through TXN-012, as an experimental native durable core. [ADR 0019](../adr/0019-m02-durable-core.md) specifies the physical action codec and isolation/recovery decisions. SQL, PostgreSQL wire compatibility, catalog/service APIs and production E3/E4 qualification remain their own milestones.

## Reproducible crash evidence

`fixtures/transactions/commit-boundaries.txt` is a fixed minimized cross-participant workload's failure-index corpus: one attempted transaction, one row, job, event and offset mutation, and thirteen record/sync boundaries, including successful controls. The harness owns its acknowledgment boolean independently of the engine status. After dropping the old engine and losing unsynced file data, it reopens, extracts every participant and ledger, checks full/absent semantics, then commits and reopens again to prove continued progress. Unknown outcome does not automatically imply abort.

Recovery's CLR workload contains one page, one loser and one patch: crash/failure after each CLR/ABORT/END boundary, reopen, redo/resume, reopen again, and verify exactly one effective compensation. Split/abort separately preserves an explicitly selected complete unknown-outcome top action and checks every surviving primary row and the failed reservation's gap. Seeded isolation histories record actual reads/writes and accepted attempts; an independent oracle searches serial permutations without using the lock manager or commit ordering as proof.

`crash-transactions` is a test driver, not a server/CLI release. The parent stops it at BEGIN, completed envelope, COMMIT record, successful flush before publication/response, and observed ACK. The parent writes/syncs the ACK oracle outside the database, sends a real process kill, waits for the child to exit, removes only that test directory's orphan ownership lock, and opens the database. Rows, primary lookup, ledger, job, event and offset state must agree. A successful sync and an ACK both require the full commit on reopen.

## Native API and resource contract

- `vetra-embedded::Database::open(path, lineage, limits)` acquires exclusive local ownership, validates WAL/data lineage, completes recovery, validates physical root/allocator/identity history and installs one transaction core. `from_log` is the injectable owned-provider entry point and also completes loser recovery. Opening starts no workers, network runtime or dispatchers.
- `begin(Isolation, Context)` returns a drop-safe transaction. Context is supplied by a **trusted in-process adapter** with principal and read/write object capabilities; unauthorized native operations fail the explicit transaction. This is not a network authentication boundary. Caller metadata is not trusted truth; no credentials or ambient process environment are automatically recorded.
- Point keys use structural byte ordering, at most 2048 bytes. Native scans use inclusive optional lower/upper bounds; None represents infinity. Fields use the specified canonical codec (NULL, bytes, UTF-8, u64, i64, bool). SQL key ordering, collation, SQL NULL uniqueness, FK/check constraints and wire SQLSTATE conformance are not advertised by these APIs.
- Defaults: 256 active attempts, 4096 logical operations/read predicates per attempt, 16 MiB logical and prepared physical staging budget, 8192 held/waiting locks, 1024 total transaction/explicit snapshot pins, 5-second transaction-lock wait and 256 MiB logical history budget. Savepoint names at most 128 bytes; at most 64 nested savepoints. Envelopes at most 16 MiB; metadata at most 16 KiB/64 entries; groups at most 256 attempts and 16 MiB envelopes. Row/page/allocator limits remain the M01 resident-tree defaults. Physical COW staging can reject a value/transaction below the envelope's nominal maximum because old + replacement pages/metadata must fit.
- Normal WAL mutation budget is 256 MiB, with a separate 256 MiB CLR/ABORT/END reserve. Open bounds retained WAL at 512 MiB. Retained byte caches and COW staging have bounded but significant memory/write amplification; no out-of-core performance or production capacity is promised. A real full disk must have space restored for recovery. Failed sync or structural/commit I/O poisons all future write commits until reopen; it never produces a successful commit reply.
- A group's complete physical action batches and logical envelopes precede one final flush. Visibility and lock release happen together after durability. Prepared participants cannot perform external callbacks/I/O of their own. Ledger is returned as immutable-by-copy committed envelopes; no ordinary mutation API edits it.
- Outcomes take database/timeline/attempt and return Committed(CSN), Aborted or Unknown. Missing identities stay Unknown. Complete records plus successful recovery prove decisions; lost responses require lookup/application idempotency. No automatic idempotency key semantics are advertised.
- Vacuum removes obsolete/aborted serving entries and primary candidates through the same durable structural boundary. It never deletes ledger/schema history. Active transaction pins hold their basis; explicit owner/kind pins expose optional caller-supplied expiry ticks. `vacuum(now)` makes expired snapshots unusable before reclamation. Savepoint rollback conservatively retains acquired locks until full transaction end; released/nested savepoint lookup uses the declared native contract.
- Checkpoints are durable complete table records, not permission to recycle WAL. Startup currently validates/scans all retained WAL and replays physical root histories; there is no checkpoint-only startup, segment recycling, history expiration, live physical backup or PITR claim. Backup/service pins preserve serving horizons for future adapters; those services are still stubs.
- Writable platform/ownership rules are inherited from M01: trusted canonical local paths, restrictive permissions, one process, symlink rejection, no NFS/SMB/Windows. A process crash leaves `owner.lock`; prove the old owner/handles stopped before removing it. Tests do that only for their own exited child.

## Delivery and review

Implementation: [PR #135](https://github.com/ulrichheringer/vetradb/pull/135), stacked on M01 PR #134. The complete local gate passed with both Rust 1.85.0 and 1.97.1 on macOS ARM/APFS. [Cross-platform CI evidence](https://github.com/ulrichheringer/vetradb/actions?query=branch%3Afeat%2Fm02-durable-transactions) runs the same complete gate; issue completion records link its successful run.

M02 is an experimental native durability/isolation milestone. Its issue closure is based on the APIs, regression/oracle mappings and passing native CI above. Merge, architecture/release ratification and production platform qualification remain separate steps. No SQL or production release is created by closing this epic.
