# Governance

The repository owner is the initial maintainer. The project may add maintainers through a documented nomination/review process as contributions grow. Roles and release responsibilities must remain visible.

Routine decisions happen in issues and pull requests. Changes to storage formats, isolation, history semantics, compatibility guarantees, security boundaries or replication need an accepted RFC/ADR. Maintain a public record of the alternatives, correctness impact and migration plan. New decisions supersede prior ADRs without erasing them.

A milestone closes only when its exit gate has reviewed evidence. Version 1.0 means the declared single-node scope passes qualification; it does not imply full PostgreSQL feature parity or HA. Release scope changes must update the compatibility matrix, roadmap and affected issues.

Respectful technical disagreement is welcome. Harassment, doxxing, threats, discriminatory conduct and publishing private credentials are prohibited. Maintainers may remove harmful content and restrict participation with a recorded reason when appropriate. Report conduct concerns privately to the repository owner through GitHub's available private contact/reporting channels; do not post sensitive details in a public issue.

The foundation governance issue will ratify maintainer roles, review/release policy and a formal code-of-conduct reporting route before external contributor onboarding expands.
